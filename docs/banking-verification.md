# 기관 기능별 실사용 확인 범위

2026-10-15에 2026-09-30~2026-10-15의 기존 웹 작업 기록을 검토했다. 은행·인증기관의 판정과 로컬 처리 상태를 구분했으며, 이 검토를 위한 추가 금융 요청은 보내지 않았다. 아래는 기록의 판정만 요약한 것으로 계좌·금액·명의·인증서·세션 식별자·응답 원문은 포함하지 않는다.

**실사용 확인**은 관찰한 경로의 성공 근거가 있다는 뜻이다. **일부 실사용 확인**은 같은 기능 안에 확인된 경로와 미확인 경로가 함께 있다는 뜻이다. 현재 세션의 유효성, 다른 계좌·사용자·인증 분기의 성공을 보장하지 않는다. 합성 테스트의 통과와 실사용 확인은 별개다.

| 기능 | 최근 기록에서 확인한 내용 | 아직 실사용 확인이 필요한 범위 |
| --- | --- | --- |
| 하나인증서 신규 발급 | SMS 요청·검증, 신분증 인증, 본인계좌 확인, 인증서 발급 및 완료 성공 | 신분증 종류별·예외 인증 분기 전체; 공동·금융인증서 신규 발급은 미지원 |
| 하나인증서 로그인 | 서명 로그인 성공 | 다른 인증·복구 분기 전체 |
| 공동인증서 로그인·조회 | 최근 웹 작업 기록에 기관 성공 판정 없음 | 해당 로그인과 계좌·내역·보안 조회 경로 |
| 계좌·잔액 | 하나인증서 로그인에서 목록과 잔액 응답 확인 | 공동인증서 경로 |
| 거래 내역 | 하나인증서 목록·은행 상세 성공. 2026-10-11 통합 조회에서 계좌 선행 확인·최근 구간 수락과 `pagination_complete=true` 확인 | 과거 구간·다음 페이지 연결, JSON/CSV 저장, 상세 유형 전체, 공동인증서 경로 |
| 이체 내역 | 하나인증서 목록 응답 성공 | 이체 내역 화면의 별도 상세 조회, 공동인증서 경로. 이체 결과 재조회의 상세 확인과 구별 |
| 보안매체·한도 | 하나인증서 이체한도 조회(`limits`) 성공 | `limit-exception`, `security-media`, `otp`, `otp-accident`, `mobile-otp`, 공동인증서 경로 |
| 원화 이체 | 준비·확인을 거쳐 실행 응답 `accepted=true`, `original_result_success=true`, `transfer_sent=true` | 관찰한 은행 승인 분기 밖의 추가 인증 경로; 최종 이체 확정은 아래 설명 참조 |
| 이체 결과 조회 | `candidate_complete=true`, `match=account_amount_and_linked_detail` | `transfer_confirmed=false`이므로 재조회만으로 최종 이체 확정을 주장하지 않음 |
| 로그인 연장 | 2026-10-09 웹 하나인증서 연장 수락 확인. 2026-10-10 CLI 세션의 연장 효과 확인(요청 없이 595초 뒤 유지, 600초 뒤 종료) | 공동인증서 경로 |
| 내역 조회의 계좌 자동 확인 | 2026-10-11 통합 거래내역 작업의 `account` 단계 수락 확인 | 이체 내역 조회의 재로그인 분기 전체 |

과거 실패·미확인 기록도 그대로 보존한다. 신분증 인증에는 거절과 이후 성공 기록이 모두 있고, 발급용 계좌 확인에는 은행 수락 후 로컬 계좌 선택을 완료하지 못한 기록과 이후 완료 기록이 있다. 계좌·로그인·내역 조회의 기관 거절, 저장소 암호 오류, 계좌 선행 조회 누락으로 전송 전에 멈춘 기록을 이후 성공으로 덮어쓰지 않는다. 이체 실행 성공 판정도 최종 확정 미확인 때문에 실패로 바꾸지 않는다.

CLI 실행 기록은 명령 단어와 종료코드만 보관하며 기관 결과를 보관하지 않는다. 따라서 `exit_code=0`만으로 CLI 실서버 성공 범위를 넓히지 않았다. 홈택스·기업·지로의 확인 범위는 아래와 같다. 공동·금융인증서 신규 발급 미지원 상태는 유지한다.

| 기능 | 확인한 내용 | 남은 미확인 |
| --- | --- | --- |
| 기업 ID/PW 로그인·계좌 | 웹 로그인·세션 저장·계좌 조회 수락 | 인증서 로그인·인증서 세션 조회 |
| 기업 거래내역 | 웹 ID/PW 세션 원화 조회 수락·완료(빈 목록과 항목 있는 목록) | 펀드·외화·대출·다음 페이지 |
| 기업 이체 | 준비 중 일부 요청 수락은 있지만 `transfer_sent=false` | 이체 실행·결과, 다건 |
| 홈택스 로그인·사업장 | 로그인·바인딩, 사용자·사업장 목록, 조회 중 사업장 전환 성공 | 인증·전환의 모든 분기 |
| 홈택스 세금 조회 | 납부할 세액·납부 내역·환급금의 `branch=success`·조회 완료 | 전자고지·신고·보고서 |
| 홈택스 계산서 | 매출의 빈 목록 조회 `branch=success`·조회 완료 | 매입·항목 있는 목록·상세·발급 |
| 지로 고지 | CLI 국세 조회·납부와 별도로 웹 관세의 항목 있는 목록 `000`·success·완료 확인 | 웹 국세·지방세의 항목 있는 목록, 추가 공과금·통합조회·독립 상세 |
| 지로 로그인·납부내역 | 웹 PIN 로그인·등록계좌·납부내역 목록/상세 성공 | 웹 납부 실행·지방세/관세 납부 |

웹 기록에서 확인하지 못한 기업·지로·홈택스 연장 작업은 미확인으로 유지한다. 2026-10-10 별도 CLI 세션 시험의 연장 효과는 해당 명령의 설명에 구분해 표시한다. 홈택스 전체 이전 검증 플래그 `migration_live_tested=false`는 개별 조회 성공을 취소하지 않는다.

웹의 **전체 기능·지원 상태**, 작업의 검증 표시, `fin capabilities`와 `fin hana plan`은 `core/live_verification.py`의 같은 검토 결과를 사용한다. `live_tested`는 지원하는 원격 경로 전체를 검증했다는 기존 넓은 플래그이므로 `false`를 유지하고, `verification=live_partial`과 `live_verification`에 실제 확인 범위를 제공한다. 제품에 포함한 것은 이 검토 요약이며 실행 환경의 로그나 개인정보를 읽어 자동으로 검증 등급을 올리지 않는다.
