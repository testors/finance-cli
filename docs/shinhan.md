# 신한은행 연결

현재 기동 요청·명시적 세션 연장·휴대폰 확인·보안카드/실물 OTP를 사용하는 최초 신한인증서 발급·PIN 로그인·신한 계좌/대출 목록·지원 화면의 대출 계좌 상세·기존 대출 증빙 목록과 금리산정내역서 PDF 조회를 구현했습니다. 합성 검증 단계이며 실서버 수락은 확인 전입니다. 모바일 OTP를 사용하는 발급, 비대면 인증, 클라우드 인증서 내려받기, 새 증빙 신청/발송·여신증명서 PDF·거래내역·이체는 아직 제공하지 않습니다. 대출 상세에도 아래의 연결 제한이 있습니다. `fin capabilities`에 같은 범위를 표시합니다.

Python HTTP와 암호 연산만 사용합니다. 처음 연결할 때 버전 20.0.40 기본 APK를 지정합니다. 기기 정보는 자동으로 준비해 공통 설정과 함께 사용자 데이터 폴더에 저장하며, 이후에는 설치 패키지 경로를 다시 지정하지 않습니다.

```sh
fin --format json-v1 shinhan session start --apk /path/to/base.apk --send
fin --format json-v1 shinhan session status
```

첫 설정에서 임의의 16자리 hex Android ID와 기본 모델 `SM-S921N`, Android 버전 `14`로 CLI용 기기 정보를 자동 생성합니다. Android ID와 모델명을 이어 SHA-256으로 계산한 식별자를 저장하며, 이후 기동·인증서 발급·로그인에서 같은 정보를 재사용합니다. 기존 설정이나 설정 갱신 시에는 식별자를 바꾸지 않습니다. 실제 휴대폰의 기기 정보를 수집하지 않습니다.

기기 값을 따로 지정할 때만 `--device-input /path/to/device.json`을 사용합니다. 이 JSON은 문자열 `android_id`, `model`, `os_version` 세 필드를 가지며 파일 권한은 `0600`이어야 합니다. 네트워크 없이 설정만 설치하려면 `fin shinhan setup --apk /path/to/base.apk`을 사용합니다. 이미 설치된 설정은 덮어쓰지 않습니다.

기동 요청이 성공해도 로그인 성공을 뜻하지 않습니다. `session status`는 로컬 파일의 존재만 읽고, 세션의 서버 유효성을 확인하지 않습니다. 기동 시 받은 공지·강제 종료·강제 업데이트·메뉴 갱신 여부를 결과의 `intro`에 표시합니다. 서버가 메뉴 갱신을 지시하면 해당 파일을 내려받고, 다운로드 실패 시 서버 기본 메뉴·로컬 백업·기본 메뉴 순서로 복구합니다. 메뉴 준비 상태는 결과의 `menu`에 별도로 표시하며 기동 성공과 구별합니다. 공지 처리는 아직 연결 중입니다.

```sh
fin --format json-v1 shinhan session extend --send
```

연장은 저장된 쿠키를 사용합니다. 서버가 연장을 성공으로 응답해도 별도 로그인 성공이나 이후 요청의 수락을 보장하지 않습니다. 자동 연장·재로그인·HTTP 재시도는 없습니다.

출력의 `bank_result`는 `success`, `failure`, `unknown` 중 하나이며 `processing_status`와 `local_status`는 별개입니다. 저장 실패가 앞선 은행 성공을 덮어쓰지 않습니다. 응답을 해석할 수 없거나 통신이 중단되면 은행 실패로 추정하지 않습니다. 현재 표준 JSON 응답을 처리하며 해석하지 못한 형식은 `unknown`으로 남깁니다.

사용자 데이터 폴더의 `shinhan/runs/<attempt>/report.json`에는 공유 가능한 단계·상태만 기록합니다. 같은 폴더의 `response.json`과 `shinhan/session.json`, `shinhan/settings.json`에는 민감한 자료가 들어 있으므로 공유하지 마세요. 디렉터리는 `0700`, 파일은 `0600`으로 저장합니다. `--send`가 없으면 설정·기기 입력을 읽거나 서버에 요청하지 않습니다.

## 인증서 로그인 연결

`fin shinhan login --send`는 현재 은행 연결의 인증서를 우선 선택하고, 연결이 없으면 사용 중지되지 않은 인증서가 하나일 때 자동 선택합니다. 선택이 모호하면 `fin shinhan certificate list`로 확인해 `--credential`로 선택합니다. 기존 SOL뱅크 앱의 인증서를 PIN만으로 가져올 수는 없습니다. 아래 최초 발급 명령으로 준비한 인증서를 사용합니다.

보관 암호와 6자리 PIN은 각각 숨김 입력합니다. `--password-stdin`은 보관 암호 한 줄만 읽습니다. 자동화의 `--pin-file`은 소유자만 읽을 수 있는 파일의 PIN 한 줄을 읽으며, PIN을 암호 입력에서 추정하지 않습니다. 개인키·PIN salt·인증서 자료는 공통 사용자 보관함에서 scrypt/AES-GCM으로 암호화합니다. 은행 세션에는 인증서 참조만 저장합니다.

로그인은 E2E 초기화·health 확인, 인증서 서버 PIN 인증, 은행 nonce 요청, RSA 서명, 은행 로그인 순서입니다. 인증서 서버의 `RA0000`과 은행의 `SUCCESS`를 별도로 기록합니다. nonce가 없으면 새 난수로 대체하지 않습니다. 서버가 인증서 재발급을 요구하면 해당 앱 연결의 기존 인증서 사용을 중지하며, 공통 보관함의 암호화된 자료를 자동 삭제하지 않습니다.

초기 설정에 E2E 또는 은행 키패드 자료가 없는 경우 아래 명령으로 기기 정보를 유지하면서 갱신합니다.

```sh
fin shinhan setup --apk /path/to/base.apk --refresh
```

현재 로그인은 PIN·RSA 경로이며 생체·패턴·E2E 자동 재초기화는 포함하지 않습니다. `phoneNo`, `phoneCom`, `phoneInfo`, `pushToken`은 자료가 없으면 빈 문자열, VPN 상태는 `X`로 보내며 Android 기기 자료를 자동 수집하지 않습니다. 실제 서버에서 이 입력으로 로그인을 수락하는지는 확인 전입니다. 로그인 작업의 `response-*.json`은 민감한 원문이며 공유 대상에서 제외합니다.

## 최초 신한인증서 발급

은행에 등록된 휴대폰 번호가 현재 본인 휴대폰 번호와 같고, 인증에 사용할 신한 계좌와 보안카드 또는 실물 OTP가 있는 SOL 회원의 발급 경로를 제공합니다. 로그인되지 않은 CLI 세션에서 실행합니다. 모바일 OTP·비대면 확인·클라우드 내려받기가 필요한 경우에는 해당 안내와 함께 중단합니다.

```sh
fin --format json-v1 shinhan certificate issue --apk /path/to/base.apk --send
```

첫 설정의 기기 정보는 자동 생성합니다. 기존 설정이 있으면 기기 정보는 유지하고 발급용 설정을 갱신합니다. 설정 준비 후에는 `fin shinhan certificate issue --send`만으로 실행할 수 있습니다. 기동 쿠키가 없으면 기동 요청부터 진행하며, 쿠키가 있으면 기존 세션을 사용합니다. 만료된 세션을 자동 연장하거나 다시 로그인하지 않습니다.

터미널에서 안내에 따라 다음 순서로 진행합니다.

1. 휴대폰 번호가 아직 확인되지 않았다면 본인 휴대폰에서 안내된 문자를 발신합니다.
2. 약관 문서를 확인하고 동의한 뒤 성명·생년월일·주민번호 뒷부분의 첫 자리·통신사를 입력하고 수신한 문자 인증번호를 입력합니다.
3. 주민번호 뒷부분, 인증용 계좌와 계좌 비밀번호를 입력합니다. 계좌는 안내된 목록에서 선택하거나 직접 입력합니다. 이 계좌 선택은 발급 본인확인을 위한 절차입니다.
4. 보안카드의 지정된 일련번호 세 자리·첫 질문 앞 두 자리·두 번째 질문 뒤 두 자리 또는 실물 OTP를 입력합니다. 은행에서 추가 인증을 요구하면 ARS나 SMS 인증을 진행합니다.
5. 새 PIN 여섯 자리와 확인 입력, 인증서 파일을 암호화할 보관 암호와 확인 입력을 진행합니다. PIN과 보관 암호는 별개입니다.

기기 통신망 정보도 입력받지 않습니다. 발급 중 VPN 여부는 기본값 `N`, 통신망 국가코드는 정보 없음에 해당하는 빈 문자열을 사용합니다. 실제 휴대폰 상태를 측정한 값은 아니며 서버 수락은 확인 전입니다.

입력 중 취소하려면 Ctrl+C를 누릅니다. 인증 요청을 자동 재시도하지 않습니다. 입력 안내 파일 `input-*.json`은 권한 `0600`으로 저장하며, 전화번호·계좌·보안카드 질문 등이 포함되므로 공유하지 마세요. 공유할 수 있는 결과는 터미널 JSON과 `report.json`입니다.

결과의 `certificate_issuance`는 인증서 발급, `certificate_registration`은 등록 결과입니다. 뒤의 로그인 수단·간편이체 등록이나 로컬 저장에 문제가 생겨도 앞서 확인한 발급·등록 성공은 보존합니다. 발급 명령 자체는 로그인하지 않습니다. 두 결과가 성공이고 보관이 완료되면 다음 명령으로 로그인한 뒤 대출 목록을 조회할 수 있습니다.

```sh
fin --format json-v1 shinhan login --send
fin --format json-v1 shinhan loans --send
```

## 문자 발신으로 휴대폰 확인

기동 세션을 만든 뒤 터미널에서 다음 명령을 실행할 수 있습니다. 인증서 발급에 필요한 휴대폰 확인 단계이며, 이 명령만으로 인증서를 발급하거나 로그인하지는 않습니다.

```sh
fin --format json-v1 shinhan phone verify --send
```

은행이 반환한 문자 수신번호와 내용을 `sms-instructions.json` 파일에 권한 `0600`으로 저장하고 경로를 안내합니다. 별도 터미널에서 이 파일을 확인한 다음, 본인 휴대폰의 문자 앱에서 해당 번호로 내용을 그대로 전송하고 CLI에서 Enter를 누릅니다. 문자를 보내지 않았다면 Ctrl+C로 취소합니다. CLI가 휴대폰의 문자를 자동 전송하지는 않습니다.

은행이 이벤트 연결을 사용하도록 응답하면 확인 알림도 수신합니다. 문자 전송 확인 뒤 7초 동안 인증 성공이 확인되지 않으면 정해진 확인 요청을 보냅니다. 이벤트가 늦게 도착하면 연결 종료까지 결과를 기다릴 수 있습니다. 연결 오류에 대한 자동 재접속·인증 재요청은 없습니다.

결과의 `device_phone_verification`이 휴대폰 확인 판정입니다. 은행 요청의 `bank_result`와 구별하며, 확인된 번호는 은행 응답에서만 가져와 사용자 세션 파일에 보관합니다. 문자 내용·이벤트 원문·전화번호는 공유용 보고서에 넣지 않습니다. `sms-instructions.json`, `device-phone-events.json`, 응답 원문과 세션 파일은 공유하지 마세요.

## 계좌·대출 목록

로그인을 마친 세션에서 다음 명령을 사용합니다. 명령이 자동 로그인하거나 만료된 세션을 갱신하지는 않습니다.

```sh
fin --format json-v1 shinhan accounts --send
fin --format json-v1 shinhan loans --send
```

`accounts`는 표시 가능한 신한 계좌 목록을, `loans`는 그중 대출 분류의 목록을 조회합니다. `--refresh`를 추가하면 은행에 목록 새로고침을 요청합니다. 숨김 계좌와 다른 기관의 최상위 행은 선택 목록에서 제외하며 연결된 하위 계좌 정보는 보존합니다. 별도 보험 목록과 외부기관 잔액 갱신은 포함하지 않습니다.

출력에는 은행 판정·처리 상태·표시 건수 `count`와 `data_file` 경로를 반환합니다. 계좌 이름·번호·금액·통화와 상세 이동 정보는 `data_file`의 `categories[].assetList[]`에 저장하며 파일 권한은 `0600`입니다. 이 파일과 응답 원문에는 개인정보가 있으므로 공유하지 마세요. 공유용 `report.json`에는 계좌 데이터가 없습니다.

성공한 조회에서 `count: 0`은 현재 표시 조건에 맞는 목록이 비었다는 뜻입니다. 숨김 계좌까지 포함한 전체 대출 부재를 뜻하지 않습니다. 실패·미확인·본문 해석 오류에는 건수를 반환하지 않습니다. 자료 저장 오류가 은행 성공을 취소하거나 요청을 다시 실행하지 않습니다.

## 선택한 대출 계좌 상세

`loans` 결과 파일의 각 행에 있는 `index`로 선택합니다. 대출이 한 건이면 `--loan`을 생략할 수 있습니다.

```sh
fin --format json-v1 shinhan loans --send
fin --format json-v1 shinhan loan-detail --loan 1 --send
```

즉시입금·마이너스·당좌 대출 계좌관리 화면으로 연결되는 행을 지원합니다. 선택한 행의 이동 정보로 조회하며 계좌번호를 직접 입력하지 않습니다. 결과의 `data_file`에 전체 응답과 `fields`를 권한 `0600`으로 저장합니다. 금액·금리는 은행에서 받은 값을 보존합니다. 즉시입금 대출은 대출금액·잔액·금리·신규일·만기일·다음 이자 납입일을, 마이너스·당좌 대출은 한도·잔액·금리·만기일 등을 제공합니다. 해당 응답에 없는 신규일이나 기간은 추정하지 않습니다.

`detail_result`는 기본 조회 결과이며 `rate_details_result`는 마이너스 대출의 추가 금리 설명 조회 결과입니다. 후속 조회나 저장이 실패해도 먼저 받은 기본 정보와 성공 결과는 보존합니다. 새 목록 요청이 실패했거나 인증서가 바뀌면 이전 선택을 재사용하지 않습니다.

이전 설정에 메뉴가 없으면 `loan_menu_settings_refresh_required`가 나옵니다. 최초 설정에 썼던 설치 패키지로 `fin shinhan setup --apk /path/to/base.apk --refresh`를 한 번 실행하세요. 기기 식별자는 유지합니다. 신규 설치·발급 설정에서는 메뉴를 함께 준비합니다.

선택한 행의 화면 정보가 메뉴에 없으면 서버에서 확인합니다. 서버가 반환한 화면 권한과 주소를 적용하며, 화면 확인 결과는 `program_lookup_result`로 따로 표시합니다. 프로그램 공지, 별도 계좌 확인, 지원하지 않는 화면 주소 또는 파라미터 문법이 필요하면 현재 명령은 `processing_status=incomplete`와 `required_action`을 반환합니다. 이 후속 단계들은 연결 중이며 대출 부재나 은행 실패를 뜻하지 않습니다. 대출 상환·연기·한도 변경 등 관리 작업은 실행하지 않습니다.

## 기존 대출 증빙 조회

로그인한 세션에서 발급된 금리산정내역서를 조회합니다. 기간을 생략하면 은행 날짜를 기준으로 최근 1주일을 조회합니다.

```sh
fin --format json-v1 shinhan loan-documents list --send
fin --format json-v1 shinhan loan-documents list --start-date 2026-01-01 --end-date 2026-10-17 --send
fin --format json-v1 shinhan loan-documents download --document 1 --send
```

목록의 `data_file`에 문서 순번 `index`, 발급일, 상품명과 원시 항목을 저장합니다. 최근 금리산정내역서 목록의 순번을 `--document`로 선택하며 한 건이면 생략할 수 있습니다. 선택한 문서의 상세를 조회한 뒤 PDF를 `document_file`에 권한 `0600`으로 저장합니다. 이 목록은 발급 기간으로 조회하므로 계좌번호를 입력하지 않습니다. 목록 조회 실패 후에는 이전 목록을 자동 선택하지 않습니다.

은행 안내가 있으면 `notice_file`의 내용을 확인한 뒤 터미널에서 계속할 수 있습니다. 은행이 거래를 막는 공지나 추가 인증을 반환하면 해당 상태를 보고합니다. 세션 갱신이나 요청 재시도는 하지 않습니다.

여신증명서 신청 목록은 다음 명령으로 조회합니다. 연체유무확인서·대출금상환(한도해지)증명서·대출이자납입확인서가 대상이며, 신청일·발급기준일·영업점·상태를 개인 결과 파일에서 확인할 수 있습니다. 이 종류의 PDF 조회·신규 신청·팩스 및 이메일 발송은 아직 제공하지 않습니다.

```sh
fin --format json-v1 shinhan loan-documents list --type credit --send
```

`bank_result`는 은행 응답 판정이며 `detail_result`, `document_result`, `document_available`, `document_saved`는 상세 조회·PDF 뷰어 전달 분기·데이터 수신·파일 저장 상태를 구분합니다. 상세가 비어 있거나 PDF 저장이 실패해도 확인된 은행 성공을 실패로 바꾸지 않습니다. 터미널 JSON과 `report.json`만 공유하고 목록·상세·PDF·응답 원문은 공유하지 마세요.
