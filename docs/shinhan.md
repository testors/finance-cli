# 신한은행 연결

현재 기동 요청·명시적 세션 연장·휴대폰 확인·보안카드/실물 OTP를 사용하는 최초 신한인증서 발급·PIN 로그인·신한 계좌/대출 목록·지원 화면의 대출 계좌 상세·기존 대출 증빙 목록과 금리산정내역서 PDF·선택 계좌 거래내역과 이어조회를 구현했습니다. 신한 계좌와 실물 OTP를 사용한 발급은 휴대폰·본인확인부터 인증서 발급·CMP 확인·등록·암호화 보관과 후속 로그인 수단·간편이체 등록까지 실사용에서 성공했습니다. 이어서 PIN 로그인·대출 목록·즉시입금 대출 요약에서 계좌관리로 이어지는 상세 조회·세션 연장 수락과 연장 후 대출 목록 조회도 성공했습니다. 보안카드 발급 경로, 일반 계좌 목록 명령, 다른 대출 상세 경로·증빙·거래내역의 실서버 성공은 아직 확인하지 못했습니다. 모바일 OTP를 사용하는 발급, 비대면 인증, 클라우드 인증서 내려받기, 새 증빙 신청/발송·여신증명서 PDF·이체는 아직 제공하지 않습니다. 대출 상세와 거래내역에도 아래의 연결 제한이 있습니다. `fin capabilities`에 같은 범위를 표시합니다.

Python HTTP와 암호 연산만 사용합니다. 처음 연결할 때 버전 20.0.40 기본 APK를 지정합니다. 기기 정보는 자동으로 준비해 공통 설정과 함께 사용자 데이터 폴더에 저장하며, 이후에는 설치 패키지 경로를 다시 지정하지 않습니다.

```sh
fin --format json-v1 shinhan session start --apk /path/to/base.apk --send
fin --format json-v1 shinhan session status
```

첫 설정에서 임의의 16자리 hex Android ID와 기본 모델 `SM-S921N`, Android 버전 `14`로 CLI용 기기 정보를 자동 생성합니다. Android ID와 모델명을 이어 SHA-256으로 계산한 식별자를 저장하며, 이후 기동·인증서 발급·로그인에서 같은 정보를 재사용합니다. 기존 설정이나 설정 갱신 시에는 식별자를 바꾸지 않습니다. 이전 설정의 모델·OS가 빈 문자열이면 같은 기본값으로 보완합니다. 실제 휴대폰의 기기 정보를 수집하지 않습니다.

기기 값을 따로 지정할 때만 `--device-input /path/to/device.json`을 사용합니다. 이 JSON은 문자열 `android_id`, `model`, `os_version` 세 필드를 가지며 파일 권한은 `0600`이어야 합니다. 네트워크 없이 설정만 설치하려면 `fin shinhan setup --apk /path/to/base.apk`을 사용합니다. 이미 설치된 설정은 덮어쓰지 않습니다.

기동 요청이 성공해도 로그인 성공을 뜻하지 않습니다. `session status`는 로컬 파일의 존재만 읽고, 세션의 서버 유효성을 확인하지 않습니다. 기동 시 받은 공지·강제 종료·강제 업데이트·메뉴 갱신 여부를 결과의 `intro`에 표시합니다. 서버가 메뉴 갱신을 지시하면 해당 파일을 내려받고, 다운로드 실패 시 서버 기본 메뉴·로컬 백업·기본 메뉴 순서로 복구합니다. 메뉴 준비 상태는 결과의 `menu`에 별도로 표시하며 기동 성공과 구별합니다. 공지 처리는 아직 연결 중입니다.

기동 전 접속 대기(NetFunnel)를 확인합니다. 대기 중에는 인원과 예상 시간을 stderr에 표시하며, 완료 콜백을 받으면 기동 요청을 진행합니다. 공지에 표시된 “계속” 또는 “종료” 버튼은 자동 선택합니다. “계속”이면 추가 대기 확인을 수행하고, “종료”이면 중단합니다. 표시되지 않은 버튼이나 차단 우회 동작을 만들지 않습니다. 대기 결과는 `netfunnel`에 기록하고 은행의 `bank_result`와 구별합니다. 대기 키·쿠키는 일반 출력에 넣지 않습니다.

접속 대기 통신은 해당 프로토콜의 재시도 규칙을 사용합니다. SDK 단계는 최초 시도 외 최대 2회, HTTP 단계의 재시도 가능한 오류는 최대 3회이며 조건에 따라 먼저 종료합니다. 완료 요청은 별도로 처리하고 실패해도 진행된 은행 업무를 재실행하지 않습니다. 이 연결은 합성 검증 단계입니다.

```sh
fin --format json-v1 shinhan session extend --send
```

연장은 저장된 쿠키를 사용합니다. 서버가 연장을 성공으로 응답해도 별도 로그인 성공이나 이후 요청의 수락을 보장하지 않습니다. 자동 연장·재로그인·HTTP 재시도는 없습니다.

2026-10-17 실사용에서 연장 요청의 성공과 약 96초 뒤 대출 목록 조회 성공을 확인했습니다. 연장 출력의 `authentication: unverified`는 이 명령이 로그인 여부를 별도로 판정하지 않는다는 뜻입니다. 이후 조회는 최초 로그인 후 약 8분 시점이므로 서버 만료 시간과 연장으로 늘어난 시간까지 측정한 것은 아닙니다.

출력의 `bank_result`는 `success`, `failure`, `unknown` 중 하나이며 `processing_status`와 `local_status`는 별개입니다. 저장 실패가 앞선 은행 성공을 덮어쓰지 않습니다. 응답을 해석할 수 없거나 통신이 중단되면 은행 실패로 추정하지 않습니다. 현재 표준 JSON 응답을 처리하며 해석하지 못한 형식은 `unknown`으로 남깁니다.

사용자 데이터 폴더의 `shinhan/runs/<attempt>/report.json`에는 공유 가능한 단계·상태만 기록합니다. 같은 폴더의 `response.json`과 `shinhan/session.json`, `shinhan/settings.json`에는 민감한 자료가 들어 있으므로 공유하지 마세요. 디렉터리는 `0700`, 파일은 `0600`으로 저장합니다. `--send`가 없으면 설정·기기 입력을 읽거나 서버에 요청하지 않습니다.

## 인증서 로그인 연결

`fin shinhan login --send`는 현재 은행 연결의 인증서를 우선 선택하고, 연결이 없으면 사용 중지되지 않은 인증서가 하나일 때 자동 선택합니다. 선택이 모호하면 `fin shinhan certificate list`로 확인해 `--credential`로 선택합니다. 기존 SOL뱅크 앱의 인증서를 PIN만으로 가져올 수는 없습니다. 아래 최초 발급 명령으로 준비한 인증서를 사용합니다.

보관 암호와 6자리 PIN은 각각 숨김 입력합니다. `--password-stdin`은 보관 암호 한 줄만 읽습니다. 자동화의 `--pin-file`은 소유자만 읽을 수 있는 파일의 PIN 한 줄을 읽으며, PIN을 암호 입력에서 추정하지 않습니다. 개인키·PIN salt·인증서 자료는 공통 사용자 보관함에서 scrypt/AES-GCM으로 암호화합니다. 은행 세션에는 인증서 참조만 저장합니다.

공통 보관 위치를 사용하지만 모든 인증서를 여는 단일 금고 암호는 제공하지 않습니다. 신한인증서는 발급할 때 입력한 보관 암호로 열며, 하나인증서 저장소의 잠금 해제 상태나 암호를 자동으로 공유하지 않습니다. 보관 암호는 로컬 파일 보호용이며 은행에 전송하지 않습니다.

로그인은 E2E 초기화·health 확인, 인증서 서버 PIN 인증, 은행 nonce 요청, RSA 서명, 은행 로그인 순서입니다. 인증서 서버의 `RA0000`과 은행의 `SUCCESS`를 별도로 기록합니다. nonce가 없으면 새 난수로 대체하지 않습니다. 서버가 인증서 재발급을 요구하면 해당 앱 연결의 기존 인증서 사용을 중지하며, 공통 보관함의 암호화된 자료를 자동 삭제하지 않습니다.

초기 설정에 E2E 또는 은행 키패드 자료가 없는 경우 아래 명령으로 기기 정보를 유지하면서 갱신합니다.

```sh
fin shinhan setup --apk /path/to/base.apk --refresh
```

현재 로그인은 PIN·RSA 경로이며 생체·패턴·E2E 자동 재초기화는 포함하지 않습니다. `phoneNo`, `phoneCom`, `phoneInfo`, `pushToken`은 자료가 없으면 빈 문자열, VPN 상태는 `X`로 보내며 Android 기기 자료를 자동 수집하지 않습니다. 실제 서버에서 이 입력으로 로그인을 수락하는지는 확인 전입니다. 로그인 작업의 `response-*.json`은 민감한 원문이며 공유 대상에서 제외합니다.

## 최초 신한인증서 발급

은행에 등록된 휴대폰 번호가 현재 본인 휴대폰 번호와 같고, 인증에 사용할 신한 계좌와 보안카드 또는 실물 OTP가 있는 SOL 회원의 발급 경로를 제공합니다. 로그인되지 않은 CLI 세션에서 실행합니다. 모바일 OTP·비대면 확인·클라우드 내려받기가 필요한 경우에는 해당 안내와 함께 중단합니다.

```sh
fin --format json-v1 shinhan certificate issue --apk /path/to/base.apk --send
```

첫 설정의 기기 정보는 자동 생성합니다. 기존 설정이 있으면 기기 정보는 유지하고 발급용 설정을 갱신합니다. 설정 준비 후에는 `fin shinhan certificate issue --send`만으로 실행할 수 있습니다. 기동 쿠키가 없으면 기동 요청부터 진행하며, 쿠키가 있으면 기존 세션을 사용합니다. 만료된 세션을 자동 연장하거나 다시 로그인하지 않습니다.

터미널에서 안내에 따라 다음 순서로 진행합니다.

1. 발급을 새로 시작할 때마다 터미널에 표시되는 **받는 번호**로 **문자 본문 전체**를 본인 휴대폰에서 발신한 뒤 Enter를 누릅니다. 본문이 여러 줄이면 제목·인증값과 줄바꿈까지 그대로 보냅니다. JSON 파일을 열거나 전송할 필요가 없습니다. 이전 실행의 휴대폰 확인 성공을 새 실행의 인증으로 재사용하지 않습니다.
2. 발급 약관은 자동 동의합니다. 성명·생년월일·주민번호 뒷부분의 첫 자리·통신사는 화면에 보이게 입력하고, 수신한 문자 인증번호를 입력합니다. 형식이 틀리면 해당 항목만 다시 입력합니다.
3. 주민번호 뒷부분, 인증용 계좌와 계좌 비밀번호를 입력합니다. 계좌는 안내된 목록에서 선택하거나 직접 입력합니다. 이 계좌 선택은 발급 본인확인을 위한 절차입니다.
4. 보안카드의 지정된 일련번호 세 자리·첫 질문 앞 두 자리·두 번째 질문 뒤 두 자리 또는 실물 OTP를 입력합니다. 은행에서 추가 인증을 요구하면 ARS나 SMS 인증을 진행합니다.
5. 새 PIN 여섯 자리와 확인 입력, 인증서 파일을 암호화할 보관 암호와 확인 입력을 진행합니다. PIN과 보관 암호는 별개입니다.

성명 등 일반 정보, 계좌번호와 선택 순번, 추가 인증 방법은 보이는 입력을 사용합니다. PIN·비밀번호·주민번호 뒷부분 전체·인증번호·보안카드 값은 터미널에서 숨김 입력합니다. 약관 동의·등록 정보 차이 확인·계좌/보안매체 경로의 계속 진행은 자동 처리하며 기존 클라우드 인증서가 있어도 새 발급 경로를 계속합니다. 은행의 차단·실패 응답은 그대로 적용합니다.

입력값은 개별 옵션으로도 지정할 수 있습니다. 생략한 값만 해당 단계에서 입력받습니다.

```sh
fin --format json-v1 shinhan certificate issue --send \
  --name '본인 성명' --birth 900101 --gender 1 --telecom 1
```

| 입력 | 옵션 |
| --- | --- |
| 성명·생년월일 6자리·주민번호 뒷부분 첫 자리·통신사 코드 | `--name`, `--birth`, `--gender`, `--telecom` |
| 본인확인 SMS 인증번호·주민번호 뒷부분 7자리 | `--identity-sms-code`, `--resident-identity` |
| 인증용 계좌번호·계좌 비밀번호 | `--account-number`, `--account-password` |
| 실물 OTP 또는 보안카드 응답 | `--otp` 또는 `--card-serial`, `--card-first`, `--card-second` |
| 새 PIN·확인 PIN·보관 암호 | `--pin`, `--pin-repeat`, `--storage-password` |
| 추가 인증 방법·ARS 전화 kind·추가 SMS 인증번호 | `--additional-method ars\|sms`, `--additional-phone-kind`, `--additional-sms-code` |

`--pin`을 지정하고 `--pin-repeat`을 생략하면 같은 값을 확인 입력으로 사용합니다. 인자나 파일로 지정한 보관 암호도 재입력하지 않습니다. 터미널 입력에서는 두 번 확인합니다.

여러 입력을 `--input-file /path/to/issue-input.json`으로 전달할 수도 있습니다. 파일 권한은 `0600`이며 옵션 이름에서 `--`를 빼고 `-`를 `_`로 바꾼 키를 사용합니다. 일반 값과 비밀 값은 모두 문자열로 적어 앞자리 0을 보존합니다. 예를 들어 `{"name":"본인 성명","birth":"900101","gender":"1","telecom":"1"}`입니다. 같은 항목을 옵션에도 지정하면 옵션이 우선합니다. 비밀번호·PIN은 명령 이력에 남기지 않도록 이 파일로 전달할 수 있습니다.

터미널 없이도 실행할 수 있습니다. 기본적으로 생략한 값은 안내가 나오는 순서대로 stdin 한 줄씩 읽고, 진행 안내는 stderr, 최종 JSON은 stdout으로 출력합니다. 인증번호가 도착하는 시점에 파이프로 전달할 수 있으며 EOF에서는 해당 입력의 `required_action`으로 중단합니다. `--no-input`을 추가하면 stdin을 기다리지 않고 누락 항목을 즉시 반환합니다. 누락·형식 오류는 은행 실패로 판정하지 않으며 자동 재전송하지 않습니다.

문자 발신과 ARS 인증은 실제 수행한 뒤 완료 입력을 전달해야 합니다. 파이프에서는 해당 안내 후 빈 줄을 보내고, 완료 상태를 직접 제공하는 옵션은 `--sms-sent`, `--ars-completed`입니다. 파일에서는 `sms_sent`, `ars_completed`의 불리언 값을 사용합니다. 이 값은 **이번 실행의 인증 동작**에 대한 완료 입력이며, 과거에 보낸 문자의 완료 값으로 재사용하지 않습니다. CLI가 대신 문자를 보내거나 ARS를 수행하지 않으며 최종 인증 성공은 은행 응답으로 판단합니다.

기기 통신망 정보도 입력받지 않습니다. 발급 중 VPN 여부는 기본값 `N`, 통신망 국가코드는 정보 없음에 해당하는 빈 문자열을 사용합니다. 실제 휴대폰 상태를 측정한 값은 아닙니다.

입력 중 취소하려면 Ctrl+C를 누릅니다. 인증 요청을 자동 재시도하지 않습니다. 입력 안내 파일 `input-*.json`은 권한 `0600`으로 저장하며, 전화번호·계좌·보안카드 질문 등이 포함되므로 공유하지 마세요. 공유할 수 있는 결과는 터미널 JSON과 `report.json`입니다.

결과의 `certificate_issuance`는 인증서 발급, `certificate_registration`은 등록 결과입니다. 뒤의 로그인 수단·간편이체 등록이나 로컬 저장에 문제가 생겨도 앞서 확인한 발급·등록 성공은 보존합니다. 발급 명령 자체는 로그인하지 않습니다. 두 결과가 성공이고 보관이 완료되면 다음 명령으로 로그인한 뒤 대출 목록을 조회할 수 있습니다.

```sh
fin --format json-v1 shinhan login --send
fin --format json-v1 shinhan loans --send
```

발급 성공과 등록 성공은 별개입니다. `certificate_issuance: success`, `certificate_saved: true`인데 `certificate_registration: failure`이면 이미 받은 인증서를 보존하며 자동으로 재발급하거나 등록을 재시도하지 않습니다. 등록 단계의 `bank_code`·`ca_code`에서 서버 오류 코드를 확인할 수 있습니다.

## 문자 발신으로 휴대폰 확인

기동 세션을 만든 뒤 터미널에서 다음 명령을 실행할 수 있습니다. 인증서 발급에 필요한 휴대폰 확인 단계이며, 이 명령만으로 인증서를 발급하거나 로그인하지는 않습니다.

```sh
fin --format json-v1 shinhan phone verify --send
```

터미널에 **받는 번호**와 **문자 본문**을 직접 표시합니다. 본인 휴대폰의 문자메시지 앱에서 해당 번호로 표시된 본문 전체를 줄바꿈까지 그대로 전송한 다음 CLI에서 Enter를 누릅니다. 제목과 인증값이 두 줄이면 두 줄 모두 같은 문자에 넣습니다. 문자를 보내지 않았다면 Ctrl+C로 취소합니다. `phone verify`도 `--input-file`, `--sms-sent`, `--no-input`과 stdin 한 줄 완료 입력을 지원합니다. CLI가 휴대폰의 문자를 자동 전송하지는 않습니다. `sms-instructions.json`에는 같은 두 값을 권한 `0600`으로 별도 보관하며, 이 파일을 열 필요는 없습니다. 파일 저장 오류는 경고로 기록하고 문자 안내·은행 확인은 계속 진행합니다.

은행이 이벤트 연결을 사용하도록 응답하면 확인 알림도 수신합니다. 문자 전송 확인 뒤 7초 동안 인증 성공이 확인되지 않으면 정해진 확인 요청을 보냅니다. 이벤트가 늦게 도착하면 연결 종료까지 결과를 기다릴 수 있습니다. 연결 오류에 대한 자동 재접속·인증 재요청은 없습니다.

결과의 `device_phone_verification`이 휴대폰 확인 판정입니다. 은행 요청의 `bank_result`와 구별하며, 확인된 번호는 은행 응답에서만 가져와 사용자 세션 파일에 보관합니다. 문자 내용·이벤트 원문·전화번호는 공유용 보고서에 넣지 않습니다. `sms-instructions.json`, `device-phone-events.json`, 응답 원문과 세션 파일은 공유하지 마세요.

## 계좌·대출 목록

로그인을 마친 세션에서 다음 명령을 사용합니다. 명령이 자동 로그인하거나 만료된 세션을 갱신하지는 않습니다.

```sh
fin --format json-v1 shinhan accounts --send
fin --format json-v1 shinhan loans --send
```

`accounts`는 표시 가능한 신한 계좌 목록을, `loans`는 그중 대출 분류의 목록을 조회합니다. `--refresh`를 추가하면 은행에 목록 새로고침을 요청합니다. 숨김 계좌와 다른 기관의 최상위 행은 선택 목록에서 제외하며 연결된 하위 계좌 정보는 보존합니다. 별도 보험 목록과 외부기관 잔액 갱신은 포함하지 않습니다.

출력에는 은행 판정·처리 상태·표시 건수 `count`와 `data_file` 경로를 반환합니다. 계좌 이름·번호·금액·통화와 상세 이동 정보는 `data_file`의 `categories[].assetList[]`에 저장하며 파일 권한은 `0600`입니다. 이 파일과 응답 원문에는 개인정보가 있으므로 공유하지 마세요. 공유용 `report.json`에는 계좌 데이터가 없습니다.

성공한 조회에서 `count: 0`은 현재 표시 조건에 맞는 목록이 비었다는 뜻입니다. 숨김 계좌까지 포함한 전체 대출 부재를 뜻하지 않습니다. 실패·미확인·본문 해석 오류에는 건수를 반환하지 않습니다. 자료 저장 오류가 은행 성공을 취소하거나 요청을 다시 실행하지 않습니다.

## 선택한 계좌의 거래내역

최근 `accounts` 결과 파일의 `index`로 계좌를 선택합니다. 한 건이면 `--account`를 생략할 수 있습니다. 기본 조회 기간은 한국 시각 기준 최근 3개월입니다.

```sh
fin --format json-v1 shinhan accounts --send
fin --format json-v1 shinhan transactions --send
# 계좌가 여러 개일 때
fin --format json-v1 shinhan transactions --account 1 --start-date 2026-01-01 --end-date 2026-10-17 --send
# has_next가 true일 때 다음 페이지
fin --format json-v1 shinhan transactions --next --send
```

`--type all|deposit|withdrawal|atm`, `--sort latest|oldest`, `--min-amount`, `--max-amount`, `--keyword`로 조회 조건을 지정합니다. `--next`는 직전 조건과 커서를 재사용하며 다른 조회 옵션과 함께 쓰지 않습니다. 페이지는 자동으로 넘기지 않습니다. ATM 필터로 현재 페이지가 비어도 `has_next: true`이면 이어조회할 수 있습니다.

계좌 행 또는 화면에 표시되는 첫 버튼이 은행 앱의 신한 거래내역 화면으로 연결될 때 지원합니다. 해당 이동 정보의 계좌번호를 사용하며 일반 계좌 순번과 `loans` 순번을 혼용하지 않습니다. 새 목록을 조회하거나 인증서가 바뀌면 이전 이어조회는 사용할 수 없습니다.

`data_file`에는 계좌 정보 `header`와 지금까지 받은 `pages`를 권한 `0600`으로 저장합니다. 각 페이지의 `data` 첫 항목은 잔액 안내이고 그 뒤가 거래 행입니다. `count`는 누적 거래 건수이며 페이지별 안내 항목을 제외합니다. 거래 순서·중복·취소 표시와 은행 앱의 금액 변환을 보존합니다. 계좌·거래 데이터와 응답 원문은 공유하지 마세요.

계좌 정보 조회와 거래 목록 조회의 판정은 `header_result`, `page_result`로 나눕니다. 계좌 정보 조회가 실패해도 거래 목록 조회는 진행하며, 일부만 성공하면 `bank_result: partial_success`입니다. 다음 페이지나 파일 저장이 실패해도 앞서 받은 페이지와 확인된 은행 성공을 보존합니다. `processing_status`와 `local_status`는 은행 판정과 별개입니다.

화면의 로그인·계좌 보유·공지·접속 대기 조건도 적용합니다. 단축 진입 조회, 계좌 버튼 확인 팝업, 고객확인 안내, 그룹 동의와 장기 미이체 안내는 `required_action`으로 표시하며 아직 연결 중입니다. 고객확인 안내는 은행 앱처럼 조회와 별개로 발생하므로 받은 조회 결과를 함께 보존합니다. 이 명령은 합성 검증까지 완료했으며 실서버 수락은 아직 확인하지 않았습니다.

## 선택한 대출 계좌 상세

`loans` 결과 파일의 각 행에 있는 `index`로 선택합니다. 대출이 한 건이면 `--loan`을 생략할 수 있습니다.

```sh
fin --format json-v1 shinhan loans --send
fin --format json-v1 shinhan loan-detail --loan 1 --send
```

즉시입금·마이너스·당좌 대출 계좌관리 화면으로 연결되는 행을 지원합니다. 선택한 행의 이동 정보로 조회하며 계좌번호를 직접 입력하지 않습니다. 결과의 `data_file`에 전체 응답과 `fields`를 권한 `0600`으로 저장합니다. 금액·금리는 은행에서 받은 값을 보존합니다. 즉시입금 대출은 대출금액·잔액·금리·신규일·만기일·다음 이자 납입일을, 마이너스·당좌 대출은 한도·잔액·금리·만기일 등을 제공합니다. 해당 응답에 없는 신규일이나 기간은 추정하지 않습니다.

대출 요약 화면에서 계좌관리로 이동하는 경로도 지원합니다. 계좌 기본정보·대출 요약을 먼저 조회하고 선택한 대출에 해당하는 행의 정보로 상세 화면을 엽니다. 이 단계의 응답은 `entry_data_file`에 별도로 보관합니다. 계좌관리가 불가능하면 `loan_management_unavailable`로 남기며 다른 대출로 대체하지 않습니다. 요약 화면의 거래내역 전체를 조회하는 명령은 아닙니다.

2026-10-17 실사용에서 즉시입금 대출 요약→계좌관리 경로의 기본정보·요약·상세·서버 날짜 조회와 개인 파일 저장이 모두 성공했습니다. 저장된 `fields`에서 대출금액·잔액·금리·금리 설명·신규일·만기일·다음 이자 납입일이 비어 있지 않은 것을 확인했습니다. 다른 상세 이동 경로와 증빙 문서/PDF의 실서버 수락은 별도 검증 대상입니다.

`detail_result`는 기본 조회 결과이며 `rate_details_result`는 마이너스 대출의 추가 금리 설명 조회 결과입니다. 후속 조회나 저장이 실패해도 먼저 받은 기본 정보와 성공 결과는 보존합니다. 새 목록 요청이 실패했거나 인증서가 바뀌면 이전 선택을 재사용하지 않습니다.

이전 설정에 메뉴가 없으면 `loan_menu_settings_refresh_required`가 나옵니다. 최초 설정에 썼던 설치 패키지로 `fin shinhan setup --apk /path/to/base.apk --refresh`를 한 번 실행하세요. 기기 식별자는 유지합니다. 신규 설치·발급 설정에서는 메뉴를 함께 준비합니다.

선택한 행의 화면 정보가 메뉴에 없으면 서버에서 확인합니다. 서버가 반환한 화면 권한과 주소를 적용하며, 화면 확인 결과는 `program_lookup_result`로 따로 표시합니다. 계좌 보유 확인이 필요한 화면은 로그인에서 받은 입출금·오픈뱅킹 계좌 수로 판단합니다. 이 조건을 충족하지 못하면 `loan_account_required`로 중단하며, 대출이 없다는 뜻은 아닙니다.

일반 프로그램 공지는 `notice_file`에 저장하며 계속 진행 확인은 자동 처리합니다. 확인 뒤에는 진입 조건과 공지를 다시 조회합니다. 은행이 차단 공지를 반환하면 상세 조회를 보내지 않습니다. 공지 조회의 은행 판정은 `notice_lookup_result`, 응답 처리 결과는 `notice_result`로 구별합니다. 공지 조회의 통신·응답 해석 오류는 서비스 규칙에 따라 진행을 허용하지만, 성공 응답의 본문이 비어 있으면 미확인으로 중단합니다.

대출 화면에 접속 대기가 지정돼 있으면 이를 처리한 뒤 조회합니다. 이 경로에서 차단 공지를 받으면 `loan_netfunnel_blocked`로 중단하며, 기동 때의 “계속” 선택을 대신 적용하지 않습니다. 장기 미이체 안내, 그룹 동의, 지원하지 않는 화면 주소 또는 파라미터 문법이 필요하면 `processing_status=incomplete`와 `required_action`을 반환합니다. 이 후속 단계들은 연결 중이며 대출 부재나 은행 실패를 뜻하지 않습니다. 대출 상환·연기·한도 변경 등 관리 작업은 실행하지 않습니다.

## 기존 대출 증빙 조회

로그인한 세션에서 발급된 금리산정내역서를 조회합니다. 기간을 생략하면 은행 날짜를 기준으로 최근 1주일을 조회합니다.

```sh
fin --format json-v1 shinhan loan-documents list --send
fin --format json-v1 shinhan loan-documents list --start-date 2026-04-17 --end-date 2026-10-17 --send
fin --format json-v1 shinhan loan-documents download --document 1 --send
```
