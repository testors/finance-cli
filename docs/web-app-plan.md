# Finance 웹앱 구현 계획

기존 finance-cli 기능을 모바일과 PC의 웹브라우저에서도 제공한다. CLI와 에이전트 자동화는 계속 사용할 수 있으며, 웹앱은 같은 설정과 업무 기능을 이용한다. 기관별 업무 로직은 서버에서 관리하므로 해당 로직을 수정할 때 클라이언트를 다시 배포할 필요가 없다.

이 문서는 구현 계획이다. 현재 제공된 [UI 시안](../web/preview/README.md)은 가상 데이터로 동작하며 API와 실제 금융 기능은 연결되어 있지 않다.

데이터 모델(기관 로그인·대상·업무 프로필), 세션, 잠금, CLI 호환은 [업무 프로필·기관 로그인·대상 설계](profiles-and-connections.md)를 따른다. 이 문서는 화면, 어댑터·작업 실행·접속 계약, 운영 결정, 전체 구현 순서를 정한다.

## 사용자 경험

- 상단 공통 바에 **업무 프로필의 이름·유형**을 항상 표시하고 전환한다. "전체"를 선택하면 모든 대상을 모아 본다. 프로필은 탭별 표시 대상이며 서버 전역의 현재 대상이 아니다.
- 좌상단에서 **뱅킹·지로·세금**을 전환한다. 왼쪽 메뉴는 선택한 영역의 기능만 표시하고 프로필별로 각 영역의 마지막 화면을 유지한다.
- 모바일에서는 같은 영역 전환과 하단 주요 메뉴 3개·전체 메뉴를 사용한다. 모바일과 PC는 같은 API·작업·결과를 공유한다.
- **전체 작업 기록·연결 및 인증서·전체 기능과 지원 상태**는 공통 메뉴로 둔다.
- 뱅킹에서는 현재 프로필의 여러 은행 계좌를 모아 보고 로그인별로 필터링한다. 은행별 로그인 상태·조회 시각을 구별한다.
- 홈택스의 개인·사업장은 기관 로그인 아래의 대상이다. 현재 대상을 화면에 드러내어 선택하게 하며, 조회 결과·초안·진행 중인 작업에는 고정된 대상을 표시한다.
- 제공 예정인 미구현 기능은 숨기지 않고 **준비 중**으로 표시하며 비활성화한다. 서버에서도 해당 기능의 실행을 거절한다.
- 실서버에서 검증되지 않은 기능은 **실서버 미검증**으로 표시한다. 특히 이체와 계산서 발급의 확인 화면에 표시한다.
- 인증서 파일 관리와 운영 도구는 **서버에서 관리**로 구별한다. 미구현 기능과 같은 상태로 표시하지 않는다.

시안의 화면 구성·메뉴·색상·이체 및 계산서 확인 흐름을 구현 기준으로 삼는다. 시안의 예시 금액·계좌·기한·상태는 제품 데이터나 기본값으로 옮기지 않는다. 시안의 홈택스 내부 개인/사업장 선택은 대상 선택으로 통합한다.

## 기능과 CLI 연결

구현 범위의 기준은 [사용자 가이드](guide.md)와 `fin capabilities`이다. 모든 CLI 기능을 업무 화면, 공통 설정, 서버 관리 중 하나에 대응시킨다. CLI 명령의 인자나 파일 경로를 그대로 웹 API로 노출하지 않는다.

### 뱅킹

| 화면 또는 동작 | 연결할 CLI 기능 | 구현 시 보존할 동작 |
| --- | --- | --- |
| 은행 로그인 | 앱 인증, 공동인증서 로그인, 하나인증서 서명 로그인 | 기관 로그인에 지정된 자격 증명·기기·앱 등록 정보를 사용하고 필요한 인증 단계 구별 |
| 계좌 목록·잔액 | `hana accounts`, `hana onesign accounts` | 계좌 정보·조회 시각·금액 표시와 숨김 |
| 거래 내역·상세 | `hana history clock/account/page/detail` | 기간·입출금·검색·정렬·페이지 조건; 다음 페이지는 사용자가 요청 |
| 내역 저장 | `hana history export` | 조회한 페이지를 JSON·CSV로 저장 |
| 이체 내역·상세 | `hana inquiry history/detail` | 기존 이체와 서비스가 제공하는 결과 확인 |
| 원화 이체 | `hana transfer prepare/show/execute/reconcile` | 수취인·금액·수수료 확인, 명시적 실행, 중복 실행 방지, 결과 재조회 |
| 보안매체·한도 | `hana security`의 조회 기능 | 이체한도·예외·보안매체·OTP·사고·모바일 OTP 상태 조회 |
| 로그인 연장 | `hana session extend` | 요청 결과와 현재 세션 상태를 구별 |

OTP 발급·한도 변경은 실행 범위에 포함하지 않는다. 이체에서 지원하지 않는 추가 인증이 요구되면 현재 CLI의 중단 동작과 이유를 그대로 전달한다.

하나인증서 이체는 로그인 세션 하나에 이체 하나를 준비하며, 준비하는 순간 그 세션을 소모한다. 준비한 이체에는 확인 기한을 두고, 기한이 지나거나 은행 세션이 만료되면 `expired`로 표시한 뒤 새 로그인부터 다시 준비한다. 기한 값은 기관 세션 수명을 확인해 정하며 추정으로 늘리지 않는다. 결과 재조회에서 계좌·금액이 같은 내역을 찾았더라도 준비한 거래와의 연결을 확인하지 못하면 재조회만으로 해당 이체의 성공을 확정하지 않는다.

| 화면 또는 동작 | 연결할 CLI 기능 | 구현 시 보존할 동작 |
| --- | --- | --- |
| 로그인·세션 | `hometax login`, `session resume/refresh` | 공동인증서 선택과 홈택스 세션 확인·갱신 |
| 사용자·사업장 | `account show`, `business list/select` | 대상 목록 확인·등록; 대상 선택부터 업무 실행까지 직렬 실행 |
| 납부할 세액 | `tax dues` | 서비스 이용 불가와 조회 결과 0건을 구별 |
| 납부 내역 | `tax payments` | 기간·납부 구분·페이지 |
| 환급금 | `tax refunds` | 기간·지급 상태·페이지 |

| 신고 내역·접수 결과 | `returns list/status/forms` | 납세자·세목·기간·접수 상태·제출서식 |
| 접수증·신고서 | `returns receipt/document` | 서식 선택과 독립 HTML 저장 |

| 계산서 조회 | `invoice list/detail` | 매출·매입·거래처·유형·기간·상세·페이지 |
| 계산서 초안 | `invoice prepare` | 거래처·작성일·품목·공급가액·세액·청구/영수 입력 후 미리보기 |

| 계산서 발급 | `invoice issue` | 대상·발급용 인증서·초안 확인, 동일 초안의 중복 발급 시도 방지, 서비스 판정·승인번호 보존 |

계산서 발급 범위는 CLI가 지원하는 일반 과세·사업자 간 거래를 따른다. 대상이나 서명 수단이 바뀌면 기존 초안으로 발급할 수 없다. 새 세금 신고·세금 납부는 준비 중으로 표시한다.

동일 초안의 중복 발급 시도 방지는 현재 초안 파일 경로 옆의 `.issue-attempt` 표식에 의존한다. 서버는 준비 작업이 만든 초안 파일을 복사·이동하지 않고 그 경로를 작업에 고정해 발급에 사용한다. 서버의 멱등 처리를 1차 방어선으로 두고 파일 표식은 그대로 유지한다.

## 구성

초기 구현은 단일 사용자·단일 서버로 구성하되 여러 기관 로그인·대상·업무 프로필을 지원한다. Python API와 정적 웹앱을 같은 서버에서 제공하고, 브라우저에는 CLI나 Python 런타임을 포함하지 않는다.

| 구성 요소 | 구현 방향 |
| --- | --- |
| API | `src/finance_cli/server/`에 FastAPI 기반 API 추가; 서버 의존성은 `web` 선택 설치 항목으로 분리 |
| 시작 명령 | `fin server start` 추가; 기본 바인딩은 `127.0.0.1` |
| 프런트엔드 | 시안의 HTML·CSS·JavaScript를 `src/finance_cli/server/static/`으로 옮겨 제품 코드로 관리; 별도 빌드 복사 단계 없이 패키지 리소스로 포함; 초기에는 UI 프레임워크 없이 시작 |
| 업무 연결 | 작업별 어댑터로 기존 업무 함수를 재사용; HTTP 경로에서 CLI `main()`을 호출하지 않음 |
| 작업 실행 | 별도 작업 프로세스에서 수행; HTTP 요청은 작업 접수와 조회만 담당 |
| 설정·상태 저장 | 사용자 데이터 디렉터리의 SQLite 하나에 로그인·대상·프로필·세션 메타데이터·작업·실행 예약·산출물 메타데이터 저장; 기존 `profiles.json`은 형식 변경 없이 유지 |
| 세션·작업 파일 | 비공개 세션 저장소와 작업별 전용 디렉터리; 기존 개인 파일 권한·새 파일 저장 규칙 유지 |
| 배포 | 설치한 wheel만으로 정적 자산·API·CLI가 실행되는지 `tools/check_distribution.py`로 확인 |

`web/preview/`는 가상 데이터 시안으로 보존하며 실제 서비스에 연결하지 않는다. 제품용 정적 자산에서는 예시 데이터와 시연용 완료 처리를 제거한다.

### 업무 함수와 CLI 호환

현재 명령 처리에는 인자 해석·숨김 입력·파일 저장·업무 실행이 함께 있는 부분이 있다. 필요한 경로부터 인자 해석과 터미널 입출력을 분리하고, CLI와 서버가 같은 업무 함수를 호출하도록 정리한다. CLI의 옵션·JSON 결과·종료코드 계약은 유지한다.

CLI의 선택 출력 `--format json-v1`은 버전·기관·종료코드와 기존 결과를 담는 기계 판독 형식이다. [CLI 공통 규칙](guide.md#기계-판독용-출력)을 따르며, 이 외곽 형식을 웹 응답으로 그대로 전달하지 않는다. 웹 어댑터의 허용 목록·기관 판정·입력 제공 계약은 아래 기준을 별도로 적용한다.

함수 분리 전에는 해당 업무만 고정된 명령 목록과 인자 배열로 별도 프로세스에서 실행할 수 있다. 홈택스처럼 Node로 구현된 업무가 이 경우에 해당한다. 셸 문자열, 사용자 지정 실행 파일, 임의 옵션은 허용하지 않는다. 비밀은 인자·환경변수에 넣지 않고 전용 입력 채널로 전달한다. 웹 요청 프로세스에서 환경변수를 바꾸거나 표준출력을 전역 가로채지 않는다.

기관별 Node·JDK 등 기존 실행 요구사항은 서버에서 충족한다. 웹앱을 위해 기관 업무에 브라우저 자동화 의존성을 추가하지 않는다.

## 어댑터 계약

어댑터는 기존 업무 함수·명령을 웹 작업에 연결하는 계층이다. 기관마다 아래 네 가지를 정의하고 합성 테스트로 고정한다.

### 출력 분리

- 홈택스 업무 명령은 저장 파일에 세션(`cookie_jar`, storage)과 결과를 함께 쓰고, stdout에는 요약을 반환한다. 보고서 디렉터리의 `result.json`에도 쿠키가 들어 있다.
- 이런 저장 파일과 보고서 디렉터리는 비공개 세션·작업 저장소에만 두며, 그대로 산출물·다운로드·API 응답으로 제공하지 않는다. 디렉터리 전체 다운로드도 제공하지 않는다.
- API 결과와 다운로드 문서는 **어댑터별 허용 목록 필드**로 만든다. 사용자에게 필요한 세금·계좌·계산서 정보는 포함하고, 내부 세션·진단 자료(쿠키·storage·서비스 원문 교환·화면 초기화 자료·런타임 진단 등)는 제외한다. 허용 목록에 없는 새 필드는 기본적으로 제외한다.
- 보고서 HTML 같은 독립 문서는 허용 목록 검사를 거친 산출물로만 등록한다.

### 입력과 비밀 전달

- 업무 함수는 이미 `inputs` 콜백을 받는다. 웹에서는 미리 받은 값을 돌려주는 입력 제공자를 연결하고, CLI의 터미널 입력 동작은 그대로 둔다.
- 입력은 단계가 바뀌는 지점에서만 받는다. 하나인증서 이체의 계좌 비밀번호는 준비 요청과 함께 받는다. PIN은 `/confirm`에서 확인과 함께 받으며, 준비 결과의 인증 경로가 `pinHalf`일 때만 요구한다. `noAuth`와 본인 계좌 분기의 동작은 유지한다.
- 네트워크 단계 도중에 제공자에 없는 입력이 요청되면 기다리지 않는다. 그 단계를 중단하고 사유를 기록하며, 자동으로 다시 시도하지 않는다.
- 비밀은 작업 ID·단계·실행 시도에 묶는다. **그 단계를 바로 실행할 준비가 된 워커**(필요한 잠금을 얻은 워커)에만 메모리로 넘긴다. 잠금을 기다리는 작업에 비밀을 미리 맡기지 않으며, 확인 시점에 실행을 시작할 수 없으면 비밀을 받지 않고 요청을 거절한다.
- 전달 여부가 불확실하면 자동으로 다시 보내지 않는다. 해당 시도의 상태를 기록하고 새 확인을 요구한다.
- 비밀은 SQLite·작업 JSON·로그·오류 응답에 넣지 않는다.
- 하나인증서 저장소 암호는 PIN과 별개다. 서버 보관·잠금 해제 정책은 "운영 결정"에서 정한다.

### 결과 계약

작업 응답은 다음을 별도 필드로 제공한다.

- 실행 상태: `queued`, `running`, `awaiting_input`, `finished`, `cancelled`, `expired`.
- 기관 판정(`service_verdict`): 어댑터의 원래 필드를 그대로 보존한다. 예: 홈택스 `branch`·`reason`, 하나은행 `accepted`·`processing_status`·`service_status`, 이체 실행 응답의 `execution_result`.
- 재조회(`reconciliation`): 결과 조회 여부, 후보 일치, 준비한 거래와의 연결 확인 여부. 이체의 `candidate_complete`·`transfer_confirmed`처럼 실행 판정과 따로 보존한다.
- 로컬 처리(`local`): 문서·세션 저장 상태, 입력 오류, 접속 만료, 처리 오류.
- 업무 결과 요약(`outcome`): `not_started`, `success`, `partial_success`, `rejected`, `unknown`. 화면 요약용 파생 값이다.
- 출처·조회 시각·로그인·대상·세션·설정 revision·확인된 대상·산출물 ID.

`outcome`은 다음 규칙으로만 파생한다.

- 기관 판정에서 파생한다. 재조회나 로컬 처리 결과로 기존 판정을 올리거나 내리지 않는다.
- 기관의 성공 판정을 받은 작업은 재조회가 확정에 이르지 못해도 `success`를 유지하고, 재조회 상태를 별도로 표시한다.
- 실행 판정이 없는 상태(응답 유실 등)에서 재조회로 후보만 찾았다면 `unknown`이다. 거래 연결을 확인하기 전에는 `success`로 올리지 않는다.
- 확인 수준을 한 줄짜리 순차 상태로 합치지 않는다.
- 어댑터별 매핑표를 문서와 합성 테스트로 고정한다.

프로세스 종료코드나 파일 저장 성공 여부만으로 업무의 성공·실패를 결정하지 않는다. 이미 확인된 성공·부분 성공을 후속 오류로 덮어쓰지 않는다.

### 검증 수준

`fin capabilities`의 `live_tested`·`migration_live_tested` 같은 실서버 검증 정보를 기능 상태의 별도 필드로 제공한다. 검증 수준은 실행 가능 여부를 바꾸지 않는다. 다만 화면에 "실서버 미검증"으로 표시하고, 이체·계산서 발급 확인 화면에는 반드시 표시한다.

## API 계약

API 경로는 `/api/v1`로 시작한다. 웹앱과 같은 출처에서 제공하며 임의 출처의 CORS 요청은 허용하지 않는다. 아래 경로는 구현할 인터페이스이며 현재 존재하는 API가 아니다. 로그인·대상·프로필·자격 증명·기능 상태 경로는 [프로필 설계의 API](profiles-and-connections.md#api)에 있다.

| 경로 | 역할 |
| --- | --- |
| `POST /auth/enroll`, `POST /auth/logout` | 새 브라우저 접속 등록과 현재 접속 종료 |
| `GET /auth/devices`, `DELETE /auth/devices/{id}` | 등록한 브라우저 접속 확인·철회 |
| `POST /jobs` | 로그인·대상·업무 이름과 정형화한 입력으로 작업 접수; 단계에 필요한 비밀 입력 포함 가능 |
| `GET /jobs`, `GET /jobs/{id}` | 작업 목록·진행·결과·후속 입력 요구 조회; 목록에서는 수취 계좌 등 입력값 마스킹 |
| `POST /jobs/{id}/inputs` | 작업이 요청한 입력을 제출; 예상 단계와 입력 유형 검증 |
| `POST /jobs/{id}/confirm` | 준비된 이체·계산서 내용을 확인하고 실행 예약; 필요한 경우 PIN을 함께 받음 |
| `POST /jobs/{id}/cancel` | 아직 업무 요청을 시작하지 않은 작업 취소 |
| `GET /artifacts/{id}` | 허용 목록 검사를 거친 내역·보고서 다운로드 |

`POST /jobs`의 작업 이름은 `hana.accounts.list`, `hana.transfer.prepare`, `hometax.tax.dues`, `hometax.invoice.prepare`, `giro.bills.parse`처럼 서버에 등록된 값만 허용한다. 명령행·서비스 URL·파일 경로를 요청 본문으로 받지 않는다. 자료 업로드가 필요한 작업은 제한된 크기·형식으로 받은 파일을 서버가 발급한 ID로 참조한다.

기관 업무 요청의 대상 결정·소속 검사·멱등 키 규칙은 프로필 설계의 "작업 대상 고정"을 따른다. 페이지와 커서는 서버가 보관하고 클라이언트에는 불투명한 참조를 제공한다. 모든 작업·파일·후속 입력 요청에 접속 권한을 다시 검사한다.

## 실행과 복구

1. 입력·지원 상태·권한·소속을 검사하고 작업 ID와 로그인·대상·세션·설정 revision·서명 수단을 고정한다. 비밀 입력은 작업 JSON이나 로그에 넣지 않는다.
2. 필요한 잠금을 얻은 뒤 실행한다. 웹 작업은 대기열에서 기다리고, CLI는 기존 즉시 실패 동작을 유지한다. 대상 선택·확인·업무 실행을 같은 잠금으로 보호하고, 사용자 입력 대기 중에는 잠금을 해제한다. 재개할 때 대상을 다시 확인한다.
3. 이체와 계산서는 준비 결과를 저장한 뒤 사용자 확인을 기다린다. 확인 화면에는 프로필·로그인·명의·계좌 또는 사업장·수취인·금액·수수료·초안 ID·검증 수준을 표시한다. 이체 확인은 기한 안에서만 받는다.
4. 화면의 프로필을 바꿔도 준비한 작업은 기존 대상을 유지한다. 입력·설정 revision·대상·초안이 달라지면 새 준비·확인이 필요하다. 클라이언트 입력을 실행 직전에 그대로 신뢰하지 않는다.
5. 실행 예약과 시도 여부를 영속화한 뒤 한 번만 전송한다. 중복 확인이나 같은 멱등 키의 동일 요청은 기존 작업을 반환하고 다시 실행하지 않는다.
6. 전송 이후 응답 유실·프로세스 종료·서버 재시작은 자동 재전송 사유가 아니다. 확인 가능한 결과가 없으면 미확인으로 남긴다.
7. 이체는 지원하는 결과 조회로, 계산서는 목록·상세 조회로 확인한다. 재조회 결과는 기관 판정과 별도로 기록한다. 문서 저장 재처리는 업무 요청 재실행과 별개로 수행한다.
8. 재접속한 브라우저는 저장된 작업 ID로 상태를 다시 조회한다. 초기 버전은 폴링으로 구현하며, 연결 해제는 업무 취소를 뜻하지 않는다.

CLI·에이전트에서 실행한 작업도 공통 기록에 연결한다. 기록 실패는 CLI의 JSON 결과나 종료코드를 바꾸지 않는다. 과거 파일을 읽어 실행을 재현하거나 다시 보내지 않는다.

## 접속과 비밀 관리

초기 운영은 사설 네트워크 또는 VPN 안에서 접속하는 구성을 기본으로 한다. 서버를 공용 인터넷에 노출하는 기능은 기본 설정에 포함하지 않는다. 원격 브라우저 접속에는 Caddy 리버스 프록시의 HTTPS를 사용하고("운영 결정"), 인증서 금고가 있는 호스트와 프런트엔드를 별도 공개 서비스로 나누지 않는다.

웹앱 접속은 은행·홈택스 로그인과 구별한다. 최초 브라우저 등록은 서버의 로컬 관리 명령이 생성한 만료되는 일회성 코드로 진행한다. 코드는 URL·로그에 넣지 않고 한 번 사용하면 폐기한다. 이후 기기별 접속 토큰을 사용하며 서버에는 토큰 해시만 저장한다. 별도 사용자 가입 기능은 만들지 않는다.

접속 쿠키에는 `HttpOnly`, `Secure`, `SameSite=Strict`를 적용한다. 상태 변경 요청은 CSRF 토큰과 출처 검사를 함께 사용한다. 접속 만료·유휴 만료·철회·등록 시도 제한을 구현한다. 기기 토큰만으로 잔액·내역을 볼 수 있으므로 앱 잠금 같은 보조 장치는 제품 마무리 단계에서 검토한다. `localStorage`에는 접속 토큰이나 기관 비밀을 저장하지 않는다. 로컬 개발용 HTTP 설정은 프록시 뒤 운영 설정과 명시적으로 구분한다.

웹에서 받은 PIN·비밀번호는 "입력과 비밀 전달" 규칙을 따른다. 자동화에 필요한 비밀은 서버의 기존 보관·접근 방식으로 해결하며 프런트엔드에 전달하지 않는다.

산출물 다운로드는 등록된 ID에만 허용한다. HTML 보고서는 앱과 같은 권한으로 실행하지 않는다. 미리보기는 스크립트와 동일 출처 권한을 허용하지 않는 sandbox로 격리하고, 다운로드는 첨부 파일로 제공한다. 원시 응답 파일·세션 파일·금고 디렉터리는 정적 파일 경로에 포함하지 않는다.

## 운영 결정

구현 전에 정해야 하는 항목과 결정 내용이다.

| 항목 | 결정 | 상태 |
| --- | --- | --- |
| 서버 호스트 | CLI와 같이 **macOS·Linux 모두 지원**하고 두 환경에서 테스트한다. 서버·워커·비밀 보관은 OS 전용 기능에 의존하지 않는다. 기존 `core/keychain.py`는 macOS 전용이며 현재 제품 경로에 연결되어 있지 않으므로, 웹앱의 비밀 보관 기준으로 삼지 않는다 | 결정 |
| 원격 HTTPS | **Caddy 리버스 프록시**가 TLS를 종단하고 `127.0.0.1`의 API 서버로 전달한다. 서버의 기본 바인딩은 `127.0.0.1`을 유지하며 직접 TLS를 제공하지 않는다. 아래 "프록시 뒤 동작" 규칙을 따른다 | 결정 |
| 휴대폰이 신뢰하는 인증서 | Caddy의 인증서 발급 방식: 사설 호스트명에 ACME DNS 검증으로 공인 인증서를 받거나, Caddy 내부 CA(`tls internal`)를 쓰고 그 루트를 접속 기기에 설치한다. 둘 중 하나를 설치 안내에 고정한다 | 3단계 전 |
| 비밀 보관 방식 | 자동화·웹 작업에 필요한 비밀(하나인증서 저장소 암호 등)을 웹 작업마다 입력받을지, 서버가 보관·잠금 해제할지와 그 범위. macOS·Linux에서 같은 방식으로 동작해야 한다 | 5단계 전 |

### 프록시 뒤 동작

- API 서버는 루프백에서 온 요청에 대해서만 프록시 헤더(`X-Forwarded-Proto`, `X-Forwarded-For`, `X-Forwarded-Host`)를 신뢰한다. 다른 출처의 프록시 헤더는 무시한다.
- 접속 쿠키의 `Secure`, CSRF 출처 검사, 등록 코드의 유효 조건은 서버 설정의 **공개 출처(스킴·호스트·포트)** 를 기준으로 판단한다. 요청 헤더에서 출처를 추정하지 않는다.
- Caddy 설정에서 원시 응답 파일·세션 파일·금고 디렉터리 등 정적 경로를 따로 노출하지 않는다. 정적 자산은 API 서버가 제공하는 패키지 리소스만 쓴다.
- 서버는 프록시 없이 루프백으로 직접 접속하는 로컬 개발용 HTTP 설정과, Caddy 뒤에서 동작하는 운영 설정을 명시적으로 구분한다.
- 기준 `Caddyfile`은 설치 안내에 포함하고, 프록시 뒤에서 접속 등록·CSRF·산출물 다운로드가 동작하는지 로컬 Caddy와 가상 서비스로 검증한다.

## 지원 상태와 화면 연결

서버는 CLI 지원 정보, 웹 작업 등록 정보, 선택한 프로필의 로그인·대상·서명 수단 조건을 합쳐 기능 상태를 반환한다. 프런트엔드는 이 응답을 메뉴·버튼·전체 기능 목록에 동일하게 적용한다.

| 상태 | 화면 | 실행 처리 |
| --- | --- | --- |
| `available` | 사용 가능 | 권한·입력 검사 후 실행 |
| `setup_required` | 설정 필요와 사유 | 필요한 설정이 완료되기 전 실행 불가 |
| `planned` | 준비 중·비활성 | API에서도 `capability_unavailable`로 거절 |
| `local_only` | 서버에서 관리 | 원격 실행 경로 없음 |

각 기능에는 `requires_confirmation`, `requires_input`, `service`, `operation`, 해당 로그인·대상, 검증 수준을 제공한다. 구현·설정 상태와 별도로 `readiness`에 `ready`, `login_required`, `input_required`, `target_unverified`를 표시한다. `available`은 현재 로그인이나 대상 확인을 보장하지 않으므로, 업무를 실행할 때 서버가 준비 상태를 다시 확인한다. 설치된 런타임이나 선택한 프로필이 달라져도 화면에서 사용 가능하다고 추정하지 않는다. 새 CLI 기능을 추가하면 대응 화면 또는 서버 관리 분류도 함께 추가한다.

## 구현 순서와 완료 기준

이 표가 웹앱과 프로필 설계의 유일한 구현 순서다. 각 단계는 앞 단계의 완료 기준을 충족한 뒤 진행한다. 실제 업무 실행 없이 가상 서비스 응답과 로컬 테스트 서버로 검증한다.

| 단계 | 구현할 내용 | 완료 기준 |
| --- | --- | --- |
| 0. 선행 수정 | 하나인증서 이체 `execute`에서 PIN 입력을 `executing` 기록 전으로 이동 (웹과 독립) | PIN 입력 취소 시 `prepared` 유지; nonce 요청 없음; 중복 실행 차단 유지; 첫 nonce 전 실행 예약 유지 |
| 1. 모델·저장소 | `web` 선택 의존성, `fin server`(루프백 바인딩·공개 출처 설정), 패키지 내 정적 자산; SQLite의 최소 로그인·대상·업무 프로필 모델; 인증서 프로필 가져오기 | macOS·Linux에서 설치한 wheel 실행; `profiles.json` 무변경과 기존 인증서 선택 계약 유지; 명의·유형 추정 없음 |
| 2. 실행 계약 | 작업 저장·워커, 어댑터 출력 분리·허용 목록, 결과 계약 필드, 입력 제공자·비밀 전달, 세션 ID 고정·포인터·`stale`, 홈택스 잠금과 웹 대기열, 브라우저 등록·CSRF | 쿠키·세션 자료가 API·산출물에 없음; 비밀이 저장소·로그에 없음; 기관 판정 원본 보존; CLI 즉시 실패와 웹 대기 구별; 재시작 시 재전송 없음 |
| 3. 첫 화면 | 홈택스 로그인·대상 확인·등록, `hometax.tax.dues`를 워커→API→화면까지 연결, 기준 `Caddyfile` | 서비스 이용 불가와 0건 구별; 고정된 대상 표시; Caddy 프록시 뒤에서 휴대폰으로 접속 등록·조회 |
| 4. 프로필·조회 확장 | 상단 프로필·전체 보기, 대상 묶음, 여러 은행 계좌·필터, 나머지 뱅킹·홈택스 조회, 지로 자료 해석, 내역·보고서 저장, 통합 작업 기록, 연결·인증서 화면 | 늦은 응답 격리; 미조회 잔액 0원 합산 없음; 파일 소속 검사; 불완전 보고서 상태 보존; 검증 수준 표시 |
| 5. 이체·계산서 | 준비·확인·실행·재조회, 확인 기한·`expired`, 수정 계산서, 초안 경로 고정, 대상별 서명 수단 | 중복·응답 유실·재시작 시 재전송 없음; 후보 일치만으로 성공 확정 없음; 기관 성공 판정 유지; revision 변경 시 재확인; 동일 초안 중복 발급 시도 차단 |
| 6. 제품 마무리 | 모바일·PC 반응형, 접근성, 설치·이행 안내(같은 데이터 디렉터리의 CLI 갱신 포함), 재접속·복구, 앱 잠금 검토 | 현재 프로필·대상이 항상 보임; 키보드·모바일 사용 가능; 시안과 프로필 설계의 흐름 유지 |

실제 API 연결 시 화면별로 로딩·빈 결과·설정 필요·입력 필요·서비스 거절·결과 미확인 상태를 구현한다. 조회 시각과 작업 출처를 표시하고, 기간이나 대상을 바꾸면 이전 결과가 새 조건의 결과처럼 보이지 않게 한다.

### 검증 항목

- 기존 `python tools/test.py` 통과; 테스트에서 금융·세무 기관에 접속하지 않음.
- 작업별 허용 입력, 권한·CSRF·접속 철회·유휴 만료, 임의 경로·명령·요청 차단 확인.
- 프록시 뒤 동작: 루프백 외 출처의 프록시 헤더 무시, 공개 출처 기준의 `Secure` 쿠키·CSRF 검사, 로컬 Caddy 뒤에서 등록·다운로드 동작.
- 어댑터별 출력 허용 목록: 홈택스 저장 파일·보고서 `result.json`의 쿠키·storage가 API·산출물에 나타나지 않음.
- 비밀 전달: 잠금 대기 중인 작업은 비밀을 받지 않음; 불확실한 전달은 재전송하지 않음; 비밀이 SQLite·로그·오류 응답에 없음.
- 결과 매핑표: 기관 판정 원본 보존, 기관 성공 후 재조회 미확정 시 `success` 유지, 실행 판정 없이 후보만 찾으면 `unknown`.
- 기능 상태 목록과 실행 가능한 작업 목록의 일치, 준비 중 기능의 UI·API 차단, 검증 수준 표시 확인.
- CLI·웹 동시 실행, 실행 예약 직전·직후 종료, 미확인 결과 복구, 중복 확인·다른 내용의 멱등 키 확인.
- 이체 확인 기한 경과와 세션 만료 시 `expired`와 새 로그인부터 다시 준비하는 흐름.
- 서비스 성공 후 저장 실패, 수정 계산서의 부분 성공, 보고서 불완전 상태 보존 확인.
- 기간·페이지·대상 선택, 실제 업무 확인 화면, 모바일·PC 탐색과 키보드 접근 확인.
- 프로필 설계의 완료 기준 표 전체.
- 패키징 변경 시 `python -m build`로 만든 wheel을 macOS·Linux 별도 환경에 설치하여 정적 자산·API·CLI 실행 확인.

현재 제공 범위는 계획 문서와 정적 시안이다. API 서버, 새 모델, 접속 관리, 업무 실행 어댑터는 위 구현 단계에서 추가한다.
